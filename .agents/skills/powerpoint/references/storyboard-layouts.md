# Storyboard and layouts

Plan a multi-slide deck internally before coding. Capture number, objective, title, main message, concise content, density (LOW/MEDIUM/HIGH), focal point, layout, visual/image/chart/diagram need, and transition from the prior slide. Pick slide count for objective and duration, not a quota. Review the complete sequence for visual rhythm before implementation.

| Layout | Use when | Preferred construction |
| --- | --- | --- |
| Cover | Establish subject and mood | Editable title with image or abstract editable composition |
| Image-led title | Context or emotion matters | Image with reserved copy space and overlay if needed |
| Text + image | Explanation needs a concrete visual | Concise copy beside correctly cropped image |
| Statistics | A metric should be memorable | Large number, unit, interpretation, small supporting chart |
| Cards | Related distinct ideas | Two to four short, aligned messages |
| Comparison / before-after | Explain trade-off or change | Balanced columns using common criteria |
| Timeline | Explain chronology | Progressive milestones with consistent spacing |
| Process | Explain ordered steps | Numbered editable forms and connectors |
| Diagram | Explain a relationship/system | Simple editable nodes and lines |
| Chart / table | Communicate precise evidence | Native editable chart/table with units |
| Quote / question | Create a pause or interaction | Minimal copy and strong hierarchy |
| Case study | Demonstrate application | Context, action, result |
| Divider / conclusion / CTA | Reset or close narrative | One decisive statement and visual cue |

Do not rotate layouts mechanically. Bullets are appropriate only when they are the clearest form; otherwise split content or recast it as cards, steps, statistics, or a diagram.

Use the expanded regions and sequencing helper in [`assets/layouts.js`](../assets/layouts.js); the authoritative list and rhythm rules are in [layout library](layout-library.md).
